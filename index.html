01 / GNM 模型内部

GNM Head 是什么

GNM（Generative aNthropometric Model，Google，2026，arXiv 2607.23687，github.com/google/GNM）是一个线性 3DMM + 线性混合蒙皮（LBS）的人头统计模型，覆盖头部、眼球、牙齿牙龈和舌头，提供 numpy / PyTorch / JAX / TensorFlow 四种后端。我们使用 v3.0 head 变体（gnm_head.npz，53 MB）。

前向模型

V(α, β, θ, t) = LBS( T + Bid·α + Bexp·β + C(θ),  J(α), θ, W ) + t T 模板顶点；Bid∈ℝ253×V×3 身份基；Bexp∈ℝ383×V×3 表情基；C(θ)=Rpc·vec(rot(θ)−I) 姿态修正（36→53,463）；J(α)=J0+BJ·α 关节位置随身份变化；W∈ℝ4×V 蒙皮权重；θ 为 4 个关节的轴角旋转。

身份和表情都是线性 PCA 基，表情作用在绑定姿态（bind pose）上，然后经关节蒙皮。与 FLAME 相比，GNM 顶点数更多（17.8k vs 5k）、眼球/牙齿/舌头是模型的一部分、表情基按区域分块且维度更高。

为什么还需要条件 VAE：PCA 子空间里的"非人"样本

prior

PCA 基只回答"头能往哪些方向变"，对系数的取值没有约束：子空间里既有真人，也有大量不是人的线性组合。下面两组实验都只改系数、不改基，每列用同一种构造方式（σ 为各分量在采样器样本上的标准差，身份用 1,200 个样本、表情用 2,000 个样本估计）：a：VAE 采样（身份：female / asian；表情：happy）→ b：VAE 采样（身份：male / black；表情：surprise）→ 各维独立高斯 1σ（indep. = independent，每个分量独立抽样，忽略分量间相关性）→ 各维独立高斯 3σ → 外推 a + 4(a − b)（extrapolate：从 b 经过 a 继续沿同一方向走 4 倍距离）→ 把 a 的分量随机打乱 → 所有分量同时 +2σ。上排正面，下排侧面。

工程层面的注意事项（我们踩过的坑）
  • GNM.__call__ 被 enp.check_and_normalize_arrays 装饰，会悄悄切断 PyTorch autograd。拟合时直接调用 gnm_common 中的 vertex_positions_bind_pose / joint_positions_bind_pose / compute_pose_correctives / linear_blend_skinning。
  • PyTorch 后端内部用 torch.asarray 创建索引张量且不带 device，需要 torch.set_default_device('cuda')；prune_vertices 要在 CPU 上做完再搬到 GPU。
  • gnm_utils.expression_sigmas 是基向量范数（顶点单位），不是系数标准差；用它做正则会把表情压成 0。我们改用 ExpressionSampler 采样得到的逐分量 std 作为先验。
  • 渲染器 render_gnm 默认乘一个蓝色顶点色，输出是线性色（输入 sRGB 的 2.2 次方）；贴图渲染需传白色顶点色、关闭 shading 并做 gamma 还原。
  • 发布版 pyrender 没有 shader_program.get_shader_path，需要 monkeypatch；EGL 离屏渲染设置 PYOPENGL_PLATFORM=egl。
02 / 重建方法

基于关键点的联合优化拟合

GNM 只提供模型，不提供视频拟合代码。我们实现了一套纯 PyTorch 的优化式重建：同一个人的所有视频帧共享一组身份系数和焦距，每帧单独求解表情、头部旋转与平移，用关键点重投影误差驱动，用 GNM 的统计先验约束。

① 关键点检测

face-alignment 的 FAN（2D，SFD 检测器）逐帧输出 68 点，取最大人脸；H100 上约 55 fps。输出 landmarks (N,68,2) 与 valid 掩码。

② 相机与姿态参数化

OpenCV 针孔相机，主点在图像中心，焦距共享可学习（对数参数化，初值 1800 px）。世界→相机固定为 diag(1,−1,−1)（GNM y 向上、面朝 +z）。头部姿态 = neck 关节轴角旋转 + 三维平移，初值把 hockey_mask 中心放到相机前 1 m。

③ 裁剪模型加速

优化阶段用 prune_vertices 把 GNM 裁成只含 68 个关键点所依赖的 204 个顶点，5,276 帧联合优化 2,000 步仅需约 40 s；收敛后再用全模型前向导出 17,821 顶点网格。

优化目标

Adam · 两阶段
L = Llm + λid‖α‖² + Lexp + λt Σn‖Δ(βn/σ)‖² + λp Σn(‖Δθn‖² + ‖Δtn‖²) Llm：按部位加权的关键点像素误差平方（归一化到图像尺度，对有效帧取平均）。Lexp = mean((β/σ)² · wexp)，σ 为由语义采样器估计的逐分量先验标准差，眼部分量权重更高；舌头与瞳孔分量固定为 0（单目视频不可观测）。Δ 为同一视频相邻帧之差。

阶段 1（刚体，400 步）：只用鼻梁、外眼角、眉毛这些受表情影响小的点，优化旋转、平移和焦距。
阶段 2（全量，2000 步）：加入身份与逐帧表情，Adam + 余弦退火学习率。

表情先验为什么重要

σ from sampler

GNM 表情系数是未归一化的 PCA 系数，不同分量的典型幅度相差两个数量级（先验 std 最小 0.015、中位 0.24、最大 1.2）。最初用库里的 expression_sigmas 做正则，结果所有表情被压到接近 0，嘴永远闭着（误差 7.5 px）。改用从 ExpressionSampler 的 20 类 × 200 个样本估计的逐分量 RMS 作为 σ 后，嘴型、露齿、挑眉都能被正确拟合，误差降到 4.3 px。这个 σ 只需估计一次并缓存。

牙齿、舌头和眼睛是怎么处理的

no direct observation

牙齿：形状取平均，运动由表情基联动

牙齿形状由身份系数里的 80 个 teeth_* 分量控制，但 68 个关键点全在皮肤上，这些分量得不到数据梯度，只受 L2 正则约束，基本停在 0，即 GNM 的平均牙齿。牙齿的运动不需要额外参数：表情基覆盖全部 17,821 个顶点，lower_face_region 分量张嘴时同时移动下颌皮肤和下牙龈，上牙随 head 关节刚性运动。视频里张嘴能看到位置正确的牙齿，是表情基自带的联动。

舌头与瞳孔：固定为 0

舌头由 32 个表情分量（tongue_mean + tongue_000–030）控制，瞳孔 1 个分量。单目关键点完全观测不到，拟合时这 33 维固定为 0：舌头保持平均姿态待在口腔里，瞳孔不动。眼球转动（left_eye / right_eye 关节）同样没有观测，保持正视。

纹理：从张嘴的帧里烘出来

烘焙时牙齿 tile（1006）、舌头 tile（1007）和眼球 tile（1002 / 1004）与皮肤一样参与投影，深度测试只在它们露出来并朝向相机的帧里采样。Actor_24 的 11 段视频中，牙齿 tile 约 23%、舌头 26%、眼球内层约 53% 的纹素有真实观测，其余由 push-pull 填充。所以贴图渲染里牙齿和虹膜的颜色是真人的，形状是平均的。

局限与改进方向：牙齿大小、排列、咬合不个性化，张大嘴时偶尔出现牙齿轻微穿出或缩进嘴唇；舌头永远不动；视线固定。要改进需要口腔和眼部的直接观测：牙齿分割或牙齿轮廓关键点、虹膜检测，配合光度损失让牙齿身份分量、舌头分量和眼球关节有梯度；或者至少给舌头分量一个由语音 / 口型推断的先验。

纹理烘焙

UDIM bake
  1. UV 光栅化：按 UDIM tile 把三角形光栅化到纹理空间（皮肤 2048²，其余 512²），得到每个纹素所属三角形与重心坐标，边缘略微外扩避免接缝。
  2. 逐帧投影：每 4 帧取一帧，用拟合参数前向出全网格，纹素 3D 位置投影到视频像素，双线性采样颜色。
  3. 可见性：pyrender 渲染深度图（去掉透明角膜），纹素深度与深度图差 < 4 mm 且法线朝向相机才计入；权重 cos⁴θ。
  4. 融合与补洞：加权平均；从未观测到的纹素（后脑、口腔、颈下）用 push-pull 金字塔从邻近颜色填充。

04 / 局限与展望

目前的边界，以及下一步

局限

  • 只用了关键点：68 点只约束稀疏位置，脸颊、额头的形状由先验决定，身份偏"平均"；眼睑开合、视线、舌头均不可观测。
  • 纹理是烘焙而非反照率：拍摄光照、阴影、眼镜、胡须、头发全部烘进贴图；多帧平均 + 约 5 px 拟合误差带来轻微模糊。
  • 无头发几何：头发只是贴在头皮形状上，大幅转头时边缘会拉伸。
  • 单视角覆盖：皮肤 tile 仅约一半纹素有真实观测，后脑、颈下为填充色。
  • 颈部以下：GNM 带肩颈，但视频下边缘截断，这部分几何与纹理不可靠。

下一步

  • 光度项：加入可微渲染（nvdiffrast / pytorch3d）的像素级损失，同时求解反照率与球谐光照，提升身份细节和纹理清晰度。
  • 稠密对应：用 MediaPipe 478 点或 DECA/EMOCA 风格的稠密监督替代 68 点，约束脸颊与眼睑。
  • 眼球与视线：利用 GNM 的眼球关节与瞳孔分量，加上虹膜检测做视线估计。
  • 语音驱动：以本流程得到的 (β, θ) 序列作为训练目标，训练 audio → GNM 表情系数的驱动模型，实现 3D talking head 生成。
  • 规模化：脚本已支持批量；HDTF 400 段全量约 70 GPU·h，可直接扩展成训练数据集。
